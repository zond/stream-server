# AGENTS.md

How to change this repository without breaking what it promises. The
[README](README.md) and the reference under [docs/](docs/) say what the
server does and how an embedder uses it; this file says where things are and
which rules a change has to keep. When they disagree, the code wins and the
doc is wrong -- fix the doc that lied.

## What this repo is

A Rust library, not a program: [xtremio](https://github.com/zond/xtremio)
links the `server` crate and starts it in-process over flutter_rust_bridge,
and nothing else runs it. HTTP is for players and stremio-core only; the app
asks through `ServerHandle` ([docs/api.md](docs/api.md)).

## Licensing

The **source** is MIT and `LICENSE` must stay MIT: it contains no GPL code.
RAR is on by default through `unrar-rs`, which is GPL-3.0-or-later, so a
**program that links this library with `rar` on is GPL-3.0-or-later** -- the
obligation is the embedder's (today xtremio ships `LICENSE-GPL-3.0` and
`unrar-rs`'s own licence file), and this repo's job is to keep the fact
visible: `server/Cargo.toml`'s `license` reads `MIT AND GPL-3.0-or-later`,
the dependency and the feature both carry the explanation, and
`LICENSE-GPL-3.0` is kept verbatim so an embedder has the text. Keep those in
step; do not change `LICENSE` to GPL. `--no-default-features` links no GPL
code (RAR requests then answer `501`).

Two crates, neither builds a binary; `members` and `default-members` in the
root `Cargo.toml` are identical and the comment there says why.

## Toolchain, build, CI

`rust-toolchain.toml` pins the toolchain; CI installs the same version
explicitly in every job of `ci.yml`, so a bump is two edits. Before
committing, all of these, gated on their exit codes (never through a
`grep` or `tail`):

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings   # the workspace lints already deny warnings and clippy::all
cargo doc --no-deps --all-features && cargo doc --no-deps --all-features --document-private-items   # links must resolve in both views
cargo test
cargo test -p server --no-default-features               # the MIT build; the only place cfg(not(feature = "rar")) compiles
cargo ndk -t armeabi-v7a -t arm64-v8a check -p server --all-targets   # needs an NDK; CI runs it
```

CI (`.github/workflows/ci.yml`, the only workflow; the README's CI table)
runs those plus a Windows build and test, with no `apt install` step.

## Conventions

- **Errors**: `anyhow` in `server`, `thiserror` in `enginefs`. **Logging**: `tracing` only. **Async**: tokio; `spawn_blocking` for anything that touches the disk; `async-trait` on the backend traits. **State**: `AppState` in `server/src/state.rs`. Edition 2024, one version across both crates, conventional commit prefixes.
- **Routes, and why there are so few.** Two HTTP callers: players and stremio-core's fork (which is changed as little as possible, so its routes stay exactly as it calls them). The app is not a third: every app-facing capability is a `ServerHandle` method with no route. **A new capability is a method, never a control route**; a new byte-serving URL for a player goes in `media_router()`; `control_router()` changes only when the core fork starts calling a new path, which is a change to the core fork first. Never a token in a query string. Keep the paths and camelCase shapes the core parses; do not resurrect removed `server.js` routes without a consumer ([Removed routes](docs/api.md#removed-routes)).
- **The LAN listener serves published tokens and nothing else; a token is published by the app per cast** (`ServerHandle::publish`, `server/src/cast.rs`). Its router is `cast::router()` -- `GET`/`HEAD /cast/{token}` and a rendition's `/cast/{token}/hls/{index.m3u8,init.mp4,n.m4s}` -- and every other path is a `404`: no route of `media_router()` or `control_router()` is ever mounted there, so a stranger on the network can read what the app chose to cast, for as long as it chose to, and cannot make this device fetch, add or open anything. A new thing to cast is a new kind of media id, never a route on the LAN; renditions (step F of `docs/design/media-pipeline.md`) live under `/cast/{token}/hls/`. A token is 128 random bits, never derived from the id, memory only; the route reaches the registry by the published id alone (`media_local.rs` scans for it); `unpublish` and the listener's stop cut every body under the token (`CastBody` polls the cut first); `log_path` elides `/cast/<token>` and nothing logs a token. Loopback answers no CORS; only the LAN router does, for the Cast receiver ([LAN media listener](docs/lan-media.md)).
- **Library parity runs one way.** Where a core route and a method answer the same question (`/settings`; the per-file stats), they share one function and `embed.rs` compares them; normalisation lives in the shared function, never in the handler. A method needs no route. Everything crossing FFI stays `serde`-serializable.
- **Native code in the default build is two crates, each with its reason written here**: `aws-lc-sys` (rustls's provider and librqbit's SHA-1) and `network-interface`'s one-file shim on macOS/BSD. `cargo tree -p server -e build,normal -i cc` lists what compiles C. No new native dependency in the default set without a reason written here; otherwise behind a feature. `rar` is the only feature.
- **Tests**: unit tests beside the code, integration tests in `server/tests/` (`embed.rs`, `proxy.rs`, `drive.rs`, `proxy_downloads.rs`, ...), every server on ephemeral ports so any number run in parallel. Five ways a test passes here and fails on a runner, each learned the hard way -- check a new test against all of them:
  1. *Torrent file order.* `create_torrent` walks a directory in readdir order; never hardcode a file index -- look it up (`torrent_file_index`, `file_index`) -- and size fixture files as whole pieces.
  2. *Path spellings.* Expectations built from a `TempDir` go through `stream_server::resolved_path`, as the server's `cacheRoot` does (8.3 names on Windows, `/private/var` on macOS).
  3. *Sleeping instead of synchronising.* A bounded poll on observable state, or `start_paused`; a fixed `sleep` is a timing assertion nobody meant.
  4. *`{:?}` on a path in a needle.* `Debug` escapes the separator; match the formatting the value used.
  5. *Waiting for a real peer to connect.* A bet on the runner's network stack; peer-dependent claims belong in the enginefs tests that dial out, everything else is provable with data already on disk.
  Fixtures get a scratch root of their own, never a fixed path under the temp dir.
- **Three rules every test keeps.**
  1. *No fixed sleeps.* Wait on observable state with a bounded poll (a deadline, a short interval, a failure that says what was being waited for) or `start_paused`; a test that needs a state nothing exposes gets a `#[cfg(test)]` or doc-hidden probe for it (`PENDING.is_waiting`, `ServerHandle::proxy_cache_settled`). The one window a test may spend is the one a "nothing happens" claim is measured over, and it is named as that (`reader_less_fetch.rs`'s `TAIL`), never used to let something finish.
  2. *Every assertion must be able to fail.* For a new or changed test, revert the code hunk it covers and watch it fail, then restore. An assertion about a path nothing writes any more, or a value that was already there before the wait, passes whatever the code does, and a hunk no test fails for is untested whatever the suite says.
  3. *Copy that is pinned verbatim is pinned on purpose.* A test that compares a sentence, a log line or a wire shape word for word is the decision that it must not drift: change the copy and the test together, and never loosen the comparison to make a change pass.
- **Agent model economy**: the cheapest model adequate for the task -- small models for mechanical edits, renames and docs; strong ones for architecture, concurrency and adversarial review.

## Rules the code depends on

Each is a decision a test pins; the doc named beside it explains the behaviour to an embedder, and this list only says what a change must not undo.

- **Nothing reaches stdout, no unwinding in release** (`panic = "abort"`), **no single-instance lock** (several servers in one process is the tests' ordinary case), **no HTTPS listener** and no daemon: a library decides none of that for its host. What must stay stable is the Rust API: `ServerConfig` and its `Default`, `start`/`run`, `ServerHandle`.
- **Magnet adds block inside librqbit** (metadata first, no timeout). enginefs runs every add detached, bounded by `METADATA_RESOLVE_TIMEOUT`, in a registry keyed by info hash: routes that must answer now use `EngineFS::get_or_begin_add_magnet` and report `resolvingMetadata`/`magnet_add_failed`; routes that need the file list use `get_or_add_magnet` / `compat::get_or_create_engine` (the only path that retries a failure) and map `MagnetAddError` with `compat::engine_creation_failure`. Never call `EngineFS::add_torrent` for a bare hash or a magnet from a route, and every creation path passes the request's `tr=` trackers -- a magnet's trackers can only be set by the request that creates the engine (`magnet_with_trackers` folds them into the link, and its doc says why nothing can add them later).
- **Every removal is one step, under the `RemovalGate`**: registry and session go together, so an add in the gap cannot be handed a torrent that is leaving.
- **The pin set is not optional state.** Every want-set plan unions `pinned_files` in; everything that drops or pauses skips `is_pinned()` except the free-space arm. The server keeps no pin record: the embedder hands the set in at boot (`ServerConfig::pins`, one `PinKey` list whose torrent and link/Drive halves each store applies) and `None` means **unknown** -- sweep nothing in either store, treat every torrent as pinned, never lift -- not "no pins" ([Offline downloads](docs/storage.md#offline-downloads), *No pin set*). A per-file delete asks `drop_file_pieces` before it unlinks, holds the claim across the unlink, and `deleted_files` means bytes really left the disk, never "the path is absent". `piece_reclaim` is on for every add because the piece store can release a piece; the price is that librqbit restores every torrent paused and only the reconciler starts one, after `apply_pins` -- do not reorder that.
- **A pin is a retention property; `output_folder` decides nothing.** One torrent-data root (`settings.cacheRoot`), placement is root + info hash, nothing above `backend/librqbit.rs` reads librqbit's folder for placement, protection or accounting, and there is no relocation. A dormant pin's directory is deleted by hand only for a hash the session has never heard of; anything the session holds is deleted through it.
- **The piece store is the session's default storage, and the only place it can be** (`SessionOptions::default_storage_factory`; the persisted record names no storage). Data is one file per piece under `.pieces/<hash>/`, `DownloadInfo::path` is a name and not a file, every free-space question is asked of that one root (`reconcile::Volumes`), and there is no migration: a whole-file download already on disk is swept by the first launch handed a pin set.
- **One chunk store, two adapters** (`chunk_store::ChunkDir` under `piece_store` and `proxy_cache`). Exactly two things are parameters: staging identity (addressable for librqbit's incremental writes, anonymous for uncoalesced proxy fillers) and the commit criterion (a proxy chunk is written whole against `write_whole`'s `expected_len`; a torrent piece is committed by `ChunkDir::commit` with no length check, and must stay so: librqbit commits a padded piece short). The store is told an index, never computes one. `ChunkDir::remove` is `pub(crate)` to `enginefs` on purpose: `server` cannot name the unlink.
- **Presence means complete**, in both adapters. A piece is accepted on `on_piece_completed`, flushed by the committer thread and only then renamed into place; a read prefers the staged copy; `init` deletes only a staged copy that shadows a complete one. A proxy chunk is held in memory until whole, committed with its byte count, and a chunk whose length disagrees with its entity is refused and deleted at the read. Do not "optimise" either into a direct write.
- **Occupancy is counted, never `metadata().len()`** (`chunk_store::occupied_bytes`: `st_blocks` on Unix). The free-space floor is one rule, `enginefs::free_space_floor(volume_total)` -- a thirty-second of the volume, clamped between `CACHE_FREE_SPACE_FLOOR_MIN` and `CACHE_FREE_SPACE_FLOOR` -- and every reader calls it (the stream route's gate, the published cap, the reconciler's free-space arm, the proxy fill, the cache report); do not move it back into `server` or give a reader its own number.
- **The cache budget has one publisher** (`cache_budget::publish`, through `publish_in_turn`): the minute timer (published before the router serves), `update_settings` and `clean_cache_now`. `occupied` is what the owners count, never a walk. Do not add a second writer, and do not read the inputs outside the turn. `CacheBudget::Unknown` is an absence, not a zero: no policy is installed until something has published.
- **There is no cache cleaner and nothing walks the cache.** Every byte under the root has one owner that knows whether anybody wants it: pinned; inside a live entity's want set, promise or shared draw; slack (taken at the tick, the switch, the running-low bell, `clean_cache_now`, shutdown, boot -- and, for what a torrent announced, only once it has left the swarm); or a stray the next launch sweep takes. Everything lives under `<cacheRoot>/media-cache` (`enginefs::CACHE_DIR_NAME`, spelled through the constant everywhere, tests included); a new directory there goes on `piece_store::sweep`'s `NOT_OURS` or the next launch deletes it, and `embed.rs`'s `the_cache_directory_holds_only_what_the_sweep_spares` lists what a boot leaves there. A translated member owns nothing. Adding a category without a deleter is how the disk becomes unbounded again; adding a walk or a second door into the piece unlink (`StoreRoot::delete_pieces` is `#[cfg(test)]`) is how the have-set desyncs. Every piece unlink is `StoreRegistry::delete` under a `drop_pieces` claim, or the proxy owner's own.
- **The retention policy is wired, and it is arithmetic.** One `RetentionPolicy` per file, resident in its cell; the detector (`retention/streams.rs`) says who is consuming a file from the runs of disk their reads caused, not from a playhead; what is over the allowance goes coldest first, backend forgetting it before the store unlinks it. No policy for a pinned file, for a budget that covers the file (`Shape::Whole`), or before a budget is published. The shared set is a uniform draw, never fetched for the swarm; **do not build an availability map** (rarity was measured at <=0.15% over random). `AfterRelease::LeaveDropped` stays, or reclaimed pieces are re-downloaded at once.
- **Sharing: announce only what was chosen, never withdraw, stop before delete** ([Sharing](docs/storage.md#sharing)). The librqbit session runs under the fork's `explicit_piece_advertising`: a torrent announces nothing until `set_pieces_advertised(.., true)` names it, from its add, its initial check and its restore on. Two things name pieces: a play session's **draw** (`State::draw`) and a **pin**, advertised whole (`Engine::advertise_shares`). **Which file is being played, for sharing, is told, never inferred**: a play session exists per viewer and only a stream request carrying the player token (`p=<viewer>.<screen>`, `PlaybackQuery::player_token`, `sessions::PlayerToken`) starts or moves one (`BackendEngineFS::note_player`, `retention::sessions`) -- at once, to the file it names, or off every torrent file for a `p=` `/proxy` request -- and an older screen of the viewer than its newest is `Heard::Stale` and moves nothing. Only the current screen's open of a file its session shares is `Opener::Player`; every other open is `Engine::try_get_file_unshared`. A file draws only while a session is on it (`Backing::plays`) and once its first bytes say it is no archive (`Backing::content_shares`, `retention::sniff`) -- a check skipped only for a session the member path opened, which knows the file is a container; a request without `p=` -- a subtitle, a side file, another client, a translated source's aside reads -- never draws and never moves a session. **A member played through an id shares its own extent, across every volume of a set; a container played by URL shares nothing**: a media id's reader with a play over a member of a single-file container in a torrent puts the session on the container file with the member's byte extent (`Play::member`, `Played::Torrent`'s `member`, `Backing::played_member`), and the draw is sized from that extent's length and confined to the pieces it lies in (`Backing::narrowed`); a `p=` request for an archive file on the HTTP route (`played_through_a_translator`, or the sniff) puts the session on it sharing nothing; a member of a multi-volume set in a torrent puts the session on the set (`Played::Set`: its volumes in the member's order, each with the member's bytes in it), which is **one thing played** -- every volume opens played and sharing, a request for any of them names the same set and moves nothing, so the reader crossing a volume boundary ends nothing, and a move off the set leaves every volume at once (`PlaySessions::may_end_now` per volume) -- and the set draws **once**: the first volume due draws over the member's bytes in all of them (`Backing::played_set`, `Backing::joined`) and advertises the union, every other volume adopts that draw from a sibling (`Retention::set_draws` orders them; only a draw recorded for this set, never one a volume made played by its URL) and advertises nothing; a container behind links is a proxied entity (`Played::Elsewhere`). The liveness cell is not the session: it still follows every stream for windows and runs (`switch_to`, `hand_live_on`, as before), and never decides a share. The draw is made once (`decide_draw_if_due`, at an open or a live pass), sized against the stream's **real** read-ahead, so it waits for the film's rate (`note_duration`; a member's is the member's bytes -- its extent in one container, or in all a set's volumes -- over the duration told to those files for the draw alone, `note_set_duration`: **a member's duration gives the container no stream rate**, nor any volume, since a container's length over an episode's duration would grant every open a season's read-ahead and size the draw against it; never a scaled duration), or `DRAW_FALLBACK` of playback without one; empty when the budget cannot hold both, the whole file when the budget covers it; adopted by every later policy of the session, never redrawn or grown. **A draw is made for a member; a new member on the same file is a move**: the draw records what it was made for (`DrawnFor`: the member, or the set) and counts as shared only while that is what the sessions on its file play (`Engine::shares_now`); a session moving to another member of the file it is on -- or between the file as itself, a member of it and a set it is a volume of -- leaves the file (`PlaySessions::play`), so `EndShares` ends the old draw as a move to another file would and then forgets it under the entity's turn (`Retention::forget_draw_made_for`), and the next open draws what is played now; an empty draw made for something else advertised nothing and is replaced at once. **Nothing calls `set_pieces_advertised(.., false)` on a live torrent** -- the fork refuses it, the fake fails the test that tries, and `Backing::advertise` has no `false` at all. A play session's announced pieces are ended only with the torrent out of the swarm: the reconciler's `Decision::EndShares` (from `Conditions::shares_to_end`, the backend's advertised set against what is shared now) stops it, `Engine::end_shares` makes the advertised set again, the torrent starts again if it is still wanted -- never waiting for the dwell, and at once even if the rebuild failed -- and only then does `Engine::drop_slack` take the ended sessions' bytes, no longer advertised, on a task of its own so the next episode's reader never waits on it. A stopped (Paused or Error) torrent whose advertised set holds anything nothing shares has it made again at the top of every reconcile, before any start (the lib fake's `check_start` fails a test whose start would announce anything no draw or pin covers). No unlink on a live torrent takes a piece it advertises, whichever file's draw it is, a set's included -- the advertised set is the torrent's, read whole (`TorrentBacking::announced_now`) -- nor a piece of a draw a session plays that is recorded and not advertised yet (`Door::drawn`, read after the advertised set, `TorrentBacking::protected_now`): a set's union is advertised under the drawing volume's turn, not under the turn of the volume being unlinked, and the record comes first. **Only a player moving stops a played torrent, and only when that player is alone on it**: while a session is on the torrent (or a stream reads it), `shares_to_end` answers only for a draw a session left while no other session was on the torrent (`PlaySessions::may_end_now`); anything else -- another player's session still there, an unpin without a delete -- waits until no session is on the torrent. **A delete is explicit and happens now** (`unpin_download_locked`, `reconcile_hash_ending_shares`): whatever `seedingEnabled` says and whoever plays the torrent, it ends the deleted file's session draw (`Retention::end_play_session`), takes the cell off the file (`Live::forget`), stops the torrent, deletes the bytes and starts again only for what still needs it; only a read of that very file defers it, to that read's end (`Engine::wait_to_delete`, `run_due_deletes` at a stream's end and every tick). A restart out of an error makes the advertised set again first (`Engine::advertise_afresh`). A slack pass on a live torrent takes nothing it announced (`Backing::announced_in_swarm`); `reclaim_rest` skips what a live torrent advertises. The test fakes hold every test to it, and record every breach so one on a spawned task still fails the test: the lib fake's `violations`, checked when the test's `Counters` guard drops on the test's own task; the scenario fake's and `PinnedHandle`'s, asserted at the end of each test that uses them. Proxy and Drive entities are `Share::Nothing` and announce nothing.
- **The same policy bounds `/proxy`**, and its playhead is a byte that really went out (`Cached::body`, `Filler::take`) -- never a `Range` header, never persisted. A window is per detected consumer; `Reader::promises` is the proxy's interlock (a framed response's undelivered chunks are nobody's to take); an entity with no policy still keeps its whole extent while live. The proxy cache's key is URL + `h=` + the forwarded negotiation headers; `r=` and `p=` are out of it, a credential in `h=` is refused rather than keyed, every hit -- whole or partial -- goes through the same playlist classification before it answers or is narrowed against, and the "what it does not do" list (no revalidation, no `Vary`, no coalescing) must stay honest ([Proxied remote streams](docs/proxy.md#proxied-remote-streams)).
- **Read-ahead is a player's and only a player's.** `ProxyBacking::want` fills the pass's want-windows through a quiet source registered by the `/proxy` route for a request carrying `p=` and by every `/drive/stream` request (`ProxyRetention::note_source`; a forgotten entity drops its source, so each request registers again); a whole-budget entity is driven from the player's delivered bytes instead, since the owner runs no pass for it. A source must carry the player's negotiation headers or it fills a sibling key. A rate is not a gate (one 256 KiB read measures one). Registering is what turns it on -- nothing that is not a player's stream calls `note_source`.
- **The reconciler makes every start and stop, and why a torrent is stopped is recomputed, never stored** (`reconcile::desired()`, a pure function of conditions readable now). Decide from `TorrentHandle::run_state`, never `is_paused()` (the flag and the state are two writes; four defects got past tests that asserted the flag). "Playing" is the liveness cell (`retention::live`), no clock attached; the hysteresis stores no bit; whatever needs a torrent running now awaits `reconcile_hash(.., PlaybackStart)` after registering its activity; ending what a torrent shares is a reconcile too (`EndShares`: stop, delete, restart at once if still wanted), never a stop made anywhere else; every route that opens a torrent reader registers a stream first (grep `get_file_reader` before adding a third). `seedingEnabled` is the session's upload switch, `seeding_enabled || playback_is_live()`, recomputed on every tick and never stored.
- **The activity light reads the connection, never the disk** (`TorrentHandle::transfer_totals`, librqbit's peer counters -- not storage reads, not `downloaded`, which grows through a hash check), judged in Rust over a window with playback absent over the same window -- live readers and stream responses at each reading, and no stream start between readings (`playback_starts`), so a short play between two polls is still seen. A download of what is not a torrent counts its filler's origin bytes on the way down (`ProxySource::counting_into`); nothing else fetched over HTTP counts. The upload switch is one for the session: on while playing or while a torrent download is on its way, otherwise only with `seedingEnabled` on and not held (`set_idle_sharing_held`, the app's background hold on a handheld). It is a peek: it touches no idle clock and creates nothing. `playback_is_live` is the live fields only and must never grow to include the last-chosen file.
- **What a panel is told** (`stream_numbers.rs`) dispatches on the URL's shape through the same parsers the routes use, keeps no state, and every absence is `null`, never a zero; transfer totals are this session's and are not persisted.
- **HTTPS trusts Mozilla's compiled-in roots** through `enginefs::http_client_builder`; never build a bare `reqwest::Client` (Android's platform verifier downloads CRLs in Java per handshake -- measured as the GC storm behind an ANR).
- **The DHT is a peer source, not a requirement, and a dead one stays quiet**: librqbit's per-attempt DHT and UPnP warnings are pinned to `error`, `diagnostics::dht_health` says the conclusion once, the bootstrap list is the two hosts measured to answer (a host is added only with a `ping` behind it), and `backend/dht_bootstrap.rs` resolves the names itself -- hermetic callers use `BootstrapResolvers::offline()`. UPnP is requested only for a `Fixed` listen port.
- **`btMaxConnections` is 160 (40 peers per torrent) and applies live**; **lean mode shrinks, it does not stop**: `set_background(true)` caps peers at `LEAN_PEER_LIMIT` and prunes the table, keeps every torrent live and seeding, and a repeated `Lean` is a no-op -- prune before lowering, never after, or `Full` has nobody to re-dial.
- **The `server` crate is a plain `rlib`**: no `cdylib`, no JNI; xtremio owns the FFI and the Android initialisation.
