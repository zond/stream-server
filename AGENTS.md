# AGENTS.md

How to change this repository without breaking what it promises. The
[README](README.md) and the reference under [docs/](docs/) say what the
server does and how an embedder uses it. This file says where things are
and which rules a change has to keep. When a doc and the code disagree, the
code wins and the doc is wrong. Fix the doc that lied.

## What this repo is

This is a Rust library, not a program.
[xtremio](https://github.com/zond/xtremio) links the `server` crate and
starts it in-process over flutter_rust_bridge, and nothing else runs it.
HTTP is for players and stremio-core only. The app asks through
`ServerHandle` ([docs/api.md](docs/api.md)).

## Write for the reader, in plain order

Everything a person reads is written for that reader, not for the author.
This library has one reader, a developer, so docs, doc comments, log lines
and commit messages may use the internal name when no common word exists,
and should, since the name is what they will search for; where a common
word does exist, use it. The sentences shown to a viewer by the app -- the
refusal sentences a rendition or a pin answers with, which the app shows
as they are -- are a viewer's words: nothing internal in them.

- **One idea per sentence, in natural order.** Subject, verb, object; the
  condition after the claim, not before it. Do not front-load a sentence
  with a qualifying clause, and do not chain ideas with dashes and
  semicolons. If a sentence has to be read twice, split it.
- **Shorter beats complete.** Cut what the reader does not need in order
  to act or to understand the next line.
- **Read it aloud.** If it would sound odd said to a friend across a
  table, rewrite it.

## Licensing

The **source** is MIT, and `LICENSE` must stay MIT: it contains no GPL code.
RAR is on by default through `unrar-rs`, which is GPL-3.0-or-later, so a
**program that links this library with `rar` on is GPL-3.0-or-later**. The
obligation is the embedder's (today xtremio ships `LICENSE-GPL-3.0` and
`unrar-rs`'s own licence file). This repo's job is to keep the fact
visible. `server/Cargo.toml`'s `license` reads `MIT AND GPL-3.0-or-later`,
the dependency and the feature both carry the explanation, and
`LICENSE-GPL-3.0` is kept verbatim so an embedder has the text. Keep those
in step, and do not change `LICENSE` to GPL. `--no-default-features` links
no GPL code (RAR requests then answer `501`).

## Toolchain, build, CI

`rust-toolchain.toml` pins the toolchain. CI installs the same version
explicitly in every job of `ci.yml`. So a bump changes three places:
`rust-toolchain.toml`, the `dtolnay/rust-toolchain@<version>` line of each
job in `ci.yml`, and the version the README's Building and CI sections
name. Before committing, run all of these, gated on their exit codes (never
through a `grep` or `tail`):

```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features   # as CI; the workspace lints deny warnings and clippy::all
cargo doc --no-deps --all-features && cargo doc --no-deps --all-features --document-private-items   # links must resolve in both views
cargo test
cargo test -p server --no-default-features               # the MIT build; the only place cfg(not(feature = "rar")) compiles
cargo run -p server --example embed_thread               # the embedding example, run as CI runs it
cargo ndk -t armeabi-v7a -t arm64-v8a check -p server --all-targets --locked   # needs an NDK; CI runs it
```

CI (`.github/workflows/ci.yml`, the only workflow, listed in the README's
CI table) runs those plus a Windows build and test, with no `apt install`
step.

## Conventions

- **Errors**: `anyhow` in `server`, `thiserror` in `enginefs`. **Logging**: `tracing` only. **Async**: tokio; `spawn_blocking` for anything that touches the disk; `async-trait` on the backend traits. **State**: `AppState` in `server/src/state.rs`. Edition 2024, one version across both crates, conventional commit prefixes.
- **Routes, and why there are so few.** There are two HTTP callers: players and stremio-core's fork. The fork is changed as little as possible, so its routes stay exactly as it calls them. The app is not a third caller. Every app-facing capability is a `ServerHandle` method with no route. **A new capability is a method, never a control route.** A new byte-serving URL for a player goes in `media_router()`. `control_router()` changes only when the core fork starts calling a new path, and that is a change to the core fork first. Never put a token in a query string. Keep the paths and camelCase shapes the core parses. Do not resurrect removed `server.js` routes without a consumer ([Removed routes](docs/api.md#removed-routes)).
- **The LAN listener serves published tokens and nothing else. The app publishes a token per cast** (`ServerHandle::publish`, `server/src/cast.rs`). Its router is `cast::router()`: `GET`/`HEAD /cast/{token}` and a rendition's `/cast/{token}/stream.mp4`. Every other path is a `404`. No route of `media_router()` or `control_router()` is ever mounted there. So a stranger on the network can read what the app chose to cast, for as long as it chose to, and cannot make this device fetch, add or open anything. A new thing to cast is a new kind of media id, never a route on the LAN. Renditions (step F of `docs/design/media-pipeline.md`) are `/cast/{token}/stream.mp4`.

  A token is 128 random bits, never derived from the id, and kept in memory only. The route reaches the registry by the published id alone (`media_local.rs` scans for it). `unpublish` and the listener's stop cut every body under the token (`CastBody` polls the cut first). `log_path` elides `/cast/<token>`, and nothing logs a token. Loopback answers no CORS. Only the LAN router does, for the Cast receiver ([LAN media listener](docs/lan-media.md)).
- **Library parity runs one way.** A core route and a method that answer the same question (`/settings`; the per-file stats) share one function, and `embed.rs` compares them. Normalisation lives in the shared function, never in the handler. A method needs no route. Everything crossing FFI stays `serde`-serializable.
- **Native code in the default build is two crates, each with its reason written here**: `aws-lc-sys` (rustls's provider and librqbit's SHA-1) and `network-interface`'s one-file shim on macOS/BSD. `cargo tree -p server -e build,normal -i cc` lists what compiles C. Add no new native dependency to the default set without a reason written here. Otherwise it goes behind a feature. `rar` is the only feature a build chooses. enginefs's `test-roots`, `test-seed` and `test-hooks` are turned on by `server`'s dev-dependency alone, and never reach a release build.
- **Tests**: unit tests beside the code, integration tests in `server/tests/` (`embed.rs`, `proxy.rs`, `drive.rs`, `proxy_downloads.rs`, ...) and `enginefs/tests/tls_roots.rs` (a binary of its own, because it moves the process's `SSL_CERT_*`). Every server is on ephemeral ports, so any number run in parallel. There are five ways a test passes here and fails on a runner, each learned the hard way. Check a new test against all of them:
  1. *Torrent file order.* `create_torrent` walks a directory in readdir order. Never hardcode a file index: look it up (`torrent_file_index`, `file_index`). Size fixture files as whole pieces.
  2. *Path spellings.* Expectations built from a `TempDir` go through `stream_server::resolved_path`, as the server's `cacheRoot` does (8.3 names on Windows, `/private/var` on macOS).
  3. *Sleeping instead of synchronising.* Use a bounded poll on observable state, or `start_paused`. A fixed `sleep` is a timing assertion nobody meant.
  4. *`{:?}` on a path in a needle.* `Debug` escapes the separator. Match the formatting the value used.
  5. *Waiting for a real peer to connect.* That is a bet on the runner's network stack. Peer-dependent claims belong in the enginefs tests that dial out. Everything else is provable with data already on disk.
  Fixtures get a scratch root of their own, never a fixed path under the temp dir.
- **Three rules every test keeps.**
  1. *No fixed sleeps.* Wait on observable state with a bounded poll (a deadline, a short interval, a failure that says what was being waited for) or `start_paused`. A test that needs a state nothing exposes gets a `#[cfg(test)]` or doc-hidden probe for it (`PENDING.is_waiting`, `ServerHandle::proxy_cache_settled`). A test may spend one window: the one a "nothing happens" claim is measured over. It is named as that (`reader_less_fetch.rs`'s `TAIL`), and never used to let something finish.
  2. *Every assertion must be able to fail.* Revert the code hunk a new or changed test covers, watch the test fail, then restore the hunk. An assertion about a path nothing writes any more, or about a value that was already there before the wait, passes whatever the code does. A hunk no test fails for is untested, whatever the suite says.
  3. *Copy that is pinned verbatim is pinned on purpose.* A test that compares a sentence, a log line or a wire shape word for word is the decision that it must not drift. Change the copy and the test together. Never loosen the comparison to make a change pass.
- **The clock is a parameter.** Retention, the detector and the rendition's pure parts (`Inner::note_request`, `WaitClock`, `Speed`) take `now` from their caller, so a test drives time by passing it (`retention/scenarios.rs` replays a field session second by second). The edges read the clock and hand it in. They are `Retention::pass` (a wrapper over `pass_at`) and, in `server/src/rendition/`, the request path (`Rendition::slot`, `start_run`, `freeze`), the sink's `send` and the run task (`run.rs`'s `drive`). That is the stated exception. Nothing that decides reads the clock itself, but the rendition's edges are not injectable.

  Each question there is asked on one clock. When a run was last asked, and so when it goes idle, is read on tokio's clock (`rendition::RequestInstant`, `request_now`). That is because `drive` sleeps until that deadline with `tokio::time::sleep_until` and then compares on the same clock. A `std` reading there disagrees with the sleep under paused tokio time. The speed rule's busy time is the producer threads' real work. It is read on `std` throughout and never slept on.
- **Agent model economy**: use the cheapest model adequate for the task. Use small models for mechanical edits, renames and docs, and strong ones for architecture, concurrency and adversarial review.

## Rules the code depends on

Each rule is a decision a test pins. The doc named beside it explains the behaviour to an embedder. This list only says what a change must not undo.

- **Nothing reaches stdout, no unwinding in release** (`panic = "abort"`), **no single-instance lock** (several servers in one process is the tests' ordinary case), **no HTTPS listener** and no daemon. A library decides none of that for its host. What must stay stable is the Rust API: `ServerConfig` and its `Default`, `start`/`run`, `ServerHandle`.
- **Magnet adds block inside librqbit** (metadata first, no timeout). enginefs runs every add detached, bounded by `METADATA_RESOLVE_TIMEOUT`, in a registry keyed by info hash. Routes that must answer now use `EngineFS::get_or_begin_add_magnet` and report `resolvingMetadata`/`magnet_add_failed`. Routes that need the file list use `get_or_add_magnet` / `compat::get_or_create_engine` (the only path that retries a failure). They map `MagnetAddError` with `compat::engine_creation_failure` (a route) or `Refusal::of_magnet_add` (a media id). For a media id, `torrentUnavailable` is a wait and `torrentRefused` is not, and `MagnetAddError::failure` decides which. Never call `EngineFS::add_torrent` for a bare hash or a magnet from a route. Every creation path passes the request's `tr=` trackers, because a magnet's trackers can only be set by the request that creates the engine. `magnet_with_trackers` folds them into the link, and its doc says why nothing can add them later.
- **Every removal is one step, under the `RemovalGate`**: registry and session go together, so an add in the gap cannot be handed a torrent that is leaving.
- **The pin set is not optional state.** Every want-set plan unions `pinned_files` in. Everything that drops or pauses skips `is_pinned()`, except the free-space arm. The server keeps no pin record. The embedder hands the set in at boot (`ServerConfig::pins`, one `PinKey` list whose torrent and link/Drive halves each store applies). `None` means **unknown**, not "no pins": sweep nothing in either store, treat every torrent as pinned, never lift ([Offline downloads](docs/storage.md#offline-downloads), *No pin set*). A per-file delete asks `drop_file_pieces` before it unlinks, and holds the claim across the unlink. `deleted_files` means bytes really left the disk, never "the path is absent". `piece_reclaim` is on for every add because the piece store can release a piece. The price is that librqbit restores every torrent paused, and only the reconciler starts one, after `apply_pins`. Do not reorder that.
- **A pin is a retention property. `output_folder` decides nothing.** There is one torrent-data root (`settings.cacheRoot`), and placement is root + info hash. Nothing above `backend/librqbit.rs` reads librqbit's folder for placement, protection or accounting, and there is no relocation. A dormant pin's directory is deleted by hand only for a hash the session has never heard of. Anything the session holds is deleted through it.
- **The piece store is the session's default storage, and the only place it can be** (`SessionOptions::default_storage_factory`; the persisted record names no storage). Data is one file per piece under `.pieces/<hash>/`, and `DownloadInfo::path` is a name, not a file. Every free-space question is asked of that one root (`reconcile::Volumes`). There is no migration. The first launch handed a pin set sweeps a whole-file download already on disk.
- **One chunk store, two adapters** (`chunk_store::ChunkDir` under `piece_store` and `proxy_cache`). Exactly two things are parameters. One is staging identity: addressable for librqbit's incremental writes, anonymous for uncoalesced proxy fillers. The other is the commit criterion. A proxy chunk is written whole against `write_whole`'s `expected_len`. A torrent piece is committed by `ChunkDir::commit` with no length check, and must stay so, because librqbit commits a padded piece short. The store is told an index, never computes one. `ChunkDir::remove` is `pub(crate)` to `enginefs` on purpose, so that `server` cannot name the unlink.
- **Presence means complete**, in both adapters. A piece is accepted on `on_piece_completed`, flushed by the committer thread, and only then renamed into place. A read prefers the staged copy. `init` deletes only a staged copy that shadows a complete one. A proxy chunk is held in memory until whole, and committed with its byte count. A chunk whose length disagrees with its entity is refused and deleted at the read. Do not "optimise" either into a direct write.
- **Occupancy is counted, never `metadata().len()`** (`chunk_store::occupied_bytes`: `st_blocks` on Unix). The free-space floor is one rule, `enginefs::free_space_floor(volume_total)`: a thirty-second of the volume, clamped between `CACHE_FREE_SPACE_FLOOR_MIN` and `CACHE_FREE_SPACE_FLOOR`. Every reader calls it (the stream route's gate, the published cap, the reconciler's free-space arm, the proxy fill, the cache report). Do not move it back into `server`, and do not give a reader its own number.
- **The cache budget has one publisher** (`cache_budget::publish`, through `publish_in_turn`): the minute timer (published before the router serves), `update_settings`, `clean_cache_now` and `clear_cache`. `occupied` is what the owners count, never a walk. Do not add a second writer, and do not read the inputs outside the turn. `CacheBudget::Unknown` is an absence, not a zero: no policy is installed until something has published.
- **There is no cache cleaner and nothing walks the cache.** Every byte under the root has one owner that knows whether anybody wants it. A byte is one of these: pinned; inside a live entity's want set, promise or shared draw; slack; on `clear_cache`, anything no pin keeps; or a stray the next launch sweep takes. Slack is taken at the tick, the switch, the running-low bell, `clean_cache_now`, shutdown and boot. What a torrent announced is taken only once the torrent has left the swarm. The clear first makes what it takes slack (holds overridden, reads cut through `Engine::cut_reads`, sessions on nothing, the cell emptied, the torrent stopped as a delete stops it), and the same slack passes take it.

  Everything lives under `<cacheRoot>/media-cache` (`enginefs::CACHE_DIR_NAME`, spelled through the constant everywhere, tests included). A new directory there goes on `piece_store::sweep`'s `NOT_OURS`, or the next launch deletes it. `embed.rs`'s `the_cache_directory_holds_only_what_the_sweep_spares` lists what a boot leaves there. A translated member owns nothing. Adding a category without a deleter is how the disk becomes unbounded again. Adding a walk, or a second door into the piece unlink, is how the have-set desyncs (`StoreRoot::delete_pieces` is `#[cfg(test)]`). Every piece unlink is `StoreRegistry::delete` under a `drop_pieces` claim, or the proxy owner's own.
- **The retention policy is wired, and it is arithmetic.** There is one `RetentionPolicy` per file, resident in its cell. The detector (`retention/streams.rs`) says who is consuming a file from the runs of disk their reads caused, not from a playhead. What is over the allowance goes coldest first, and the backend forgets it before the store unlinks it. There is no policy for a pinned file, for a budget that covers the file (`Shape::Whole`), or before a budget is published. The shared set is a uniform draw, never fetched for the swarm. **Do not build an availability map**: rarity was measured at <=0.15% over random. `AfterRelease::LeaveDropped` stays, or reclaimed pieces are re-downloaded at once.
- **Sharing: announce only what was chosen, never withdraw, stop before delete** ([Sharing](docs/storage.md#sharing)). The librqbit session runs under the fork's `explicit_piece_advertising`. A torrent announces nothing until `set_pieces_advertised(.., true)` names it, from its add, its initial check and its restore on. Two things name pieces: a play session's **draw** (`State::draw`) and a **pin**, advertised whole (`Engine::advertise_shares`).

  **Which file is being played, for sharing, is told, never inferred.** A play session exists per viewer, and only the viewer's player says what it plays. It says so with a stream request carrying its token (`p=<viewer>.<screen>`, `PlaybackQuery::player_token`, `sessions::PlayerToken`), or with an id opened or published with its `PlayToken` (`open_reader`, `publish`). That starts or moves the session at once (`BackendEngineFS::note_player`, `retention::sessions`), to the file it names. A `p=` `/proxy` request moves it off every torrent file. An older screen of the viewer than its newest is `Heard::Stale` and moves nothing. Only the current screen's open of a file its session shares is `Opener::Player`. Every other open is `Engine::try_get_file_unshared`. A file draws only while a session is on it (`Backing::plays`), and only once its first bytes say it is no archive (`Backing::content_shares`, `retention::sniff`). That check is skipped only for a session the member path opened, which knows the file is a container. A request without `p=` never draws and never moves a session: a subtitle, a side file, another client, a translated source's aside reads.

  **A member played through an id shares its own extent, across every volume of a set. A container played by URL shares nothing.** A media id's reader that plays a member of a single-file container in a torrent puts the session on the container file, with the member's byte extent (`Play::member`, `Played::Torrent`'s `member`, `Backing::played_member`). The draw is sized from that extent's length and confined to the pieces it lies in (`Backing::narrowed`). A `p=` request for an archive file on the HTTP route (`played_through_a_translator`, or the sniff) puts the session on it, sharing nothing. A member of a multi-volume set in a torrent puts the session on the set (`Played::Set`: its volumes in the member's order, each with the member's bytes in it). The set is **one thing played**. Every volume opens played and sharing. A request for any of them names the same set and moves nothing, so the reader crossing a volume boundary ends nothing. A move off the set leaves every volume at once (`PlaySessions::may_end_now` per volume). The set draws **once**. The first volume due draws over the member's bytes in all of them (`Backing::played_set`, `Backing::joined`) and advertises the union. Every other volume adopts that draw from a sibling and advertises nothing. `Retention::set_draws` orders them, and a volume adopts only a draw recorded for this set, never one a volume made played by its URL. A container behind links is a proxied entity (`Played::Elsewhere`).

  The liveness cell is not the session. It still follows every stream for windows (`switch_to`, `hand_live_on`, as before). It never decides a share or whether a torrent runs.

  The draw is made once (`decide_draw_if_due`, at an open or a live pass). It is sized against the stream's **real** read-ahead, so it waits for the film's rate (`note_duration`), or for `DRAW_FALLBACK` of playback without one. A member's rate is the member's bytes (its extent in one container, or in all a set's volumes) over the duration told to those files for the draw alone (`note_set_duration`). **A member's duration gives the container no stream rate**, nor any volume. A container's length over an episode's duration would grant every open a season's read-ahead and size the draw against it. Never use a scaled duration. The draw is empty when the budget cannot hold both, and the whole file when the budget covers it. Every later policy of the session adopts it. It is never redrawn or grown.

  **A draw is made for a member. A new member on the same file is a move.** The draw records what it was made for (`DrawnFor`: the member, or the set). It counts as shared only while that is what the sessions on its file play (`Engine::shares_now`). A session may move to another member of the file it is on, or between the file as itself, a member of it and a set it is a volume of. Either move leaves the file (`PlaySessions::play`). So `EndShares` ends the old draw as a move to another file would, then forgets it under the entity's turn (`Retention::forget_draw_made_for`). The next open draws what is played now. An empty draw made for something else advertised nothing, and is replaced at once.

  **Nothing calls `set_pieces_advertised(.., false)` on a live torrent.** The fork refuses it, the fake fails the test that tries, and `Backing::advertise` has no `false` at all. A play session's announced pieces are ended only with the torrent out of the swarm. The reconciler's `Decision::EndShares` (from `Conditions::shares_to_end`, the backend's advertised set against what is shared now) stops the torrent. `Engine::end_shares` makes the advertised set again. The torrent starts again if it is still wanted, never waiting for the dwell, and at once even if the rebuild failed. Only then does `Engine::drop_slack` take the ended sessions' bytes, which are no longer advertised. It runs on a task of its own, so the next episode's reader never waits on it. A stopped (Paused or Error) torrent whose advertised set holds anything nothing shares has the set made again at the top of every reconcile, before any start. The lib fake's `check_start` fails a test whose start would announce anything no draw or pin covers.

  No unlink on a live torrent takes a piece the torrent advertises, whichever file's draw it is, a set's included. The advertised set is the torrent's, read whole (`TorrentBacking::announced_now`). Nor does an unlink take a piece of a draw a session plays that is recorded and not advertised yet (`Door::drawn`, read after the advertised set, `TorrentBacking::protected_now`). That is needed because a set's union is advertised under the drawing volume's turn, not under the turn of the volume being unlinked, and the record comes first.

  **Only a player moving stops a played torrent, and only when that player is alone on it.** While a session is on the torrent (or a stream reads it), `shares_to_end` answers only for a draw a session left while no other session was on the torrent (`PlaySessions::may_end_now`). Anything else waits until no session is on the torrent: another player's session still there, or an unpin without a delete.

  **A delete is explicit and happens now** (`unpin_download_locked`, `reconcile_hash_ending_shares`), whatever `seedingEnabled` says and whoever plays the torrent. It ends the deleted file's session draw (`Retention::end_play_session`). It also ends a volume's pieces in its set's union, recorded on the siblings, all but a piece another volume of the set lies in (`Engine::withdraw_deleted_volume`). It takes the cell off the file (`Live::forget`), stops the torrent, deletes the bytes, and starts again only for what still needs it. Only a read of that very file defers the delete, to that read's end (`Engine::wait_to_delete`, `run_due_deletes` at a stream's end and every tick). A restart out of an error makes the advertised set again first (`Engine::advertise_afresh`). A slack pass on a live torrent takes nothing it announced (`Backing::announced_in_swarm`). `reclaim_rest` skips what a live torrent advertises.

  The test fakes hold every test to these rules. They record every breach, so one on a spawned task still fails the test. The lib fake's `violations` are checked when the test's `Counters` guard drops on the test's own task. The scenario fake's and `PinnedHandle`'s are asserted at the end of each test that uses them. Proxy and Drive entities are `Share::Nothing` and announce nothing.
- **The same policy bounds `/proxy`**, and its playhead is a byte that really went out (`Cached::body`, `Filler::take`). It is never a `Range` header, and never persisted. A window is per detected consumer. `Reader::promises` is the proxy's interlock: a framed response's undelivered chunks are nobody's to take. An entity with no policy still keeps its whole extent while live. The proxy cache's key is URL + `h=` + the forwarded negotiation headers. `r=` and `p=` are out of it, and a credential in `h=` is refused rather than keyed. Every hit, whole or partial, goes through the same playlist classification before it answers or is narrowed against. The "what it does not do" list (no revalidation, no `Vary`, no coalescing) must stay honest ([Proxied remote streams](docs/proxy.md#proxied-remote-streams)).

  **Nothing is refused for naming no validator.** An entity is filed under the strongest identity there is (`routes::proxy::entity_identity`). That is what a vouched source supplies (Drive's `md5Checksum`, else `version`/`modifiedTime`), else the origin's strong `ETag` or `Last-Modified`, else the length alone. Only the origin's two ever go out as `If-Range` or onto a hit. A source this server opens retires every other generation under its key at the open (`ProxySource::retire_stale`). That is the one revalidation there is.
- **Read-ahead is a player's and only a player's.** `ProxyBacking::want` fills the pass's want-windows through a quiet source. Three things register one: the `/proxy` route for a request carrying `p=`, every `/drive/stream` request, and a media id's reader. A media id's reader registers when it is a link (or the links behind a container) opened with a `PlayToken`, and when it reads a Drive id (`ProxyRetention::note_source`, `media::registry`'s `read_ahead`). A forgotten entity drops its source, so each request registers again. A whole-budget entity is driven from the player's delivered bytes instead, since the owner runs no pass for it. A source must carry the player's negotiation headers, or it fills a sibling key. A rate is not a gate (one 256 KiB read measures one). Registering is what turns read-ahead on. Nothing that is not a player's stream calls `note_source`.
- **The reconciler makes every start and stop, and why a torrent is stopped is recomputed, never stored** (`reconcile::desired()`, a pure function of conditions readable now). Decide from `TorrentHandle::run_state`, never `is_paused()`. The flag and the state are two writes, and four defects got past tests that asserted the flag.

  **What runs a torrent is declared, never inferred.** `Conditions::held` is three things and nothing else. The first is an explicit hold (`retention::holds`): a player screen from its first `p=` request or `PlayToken` open to `release_player`, or a cast from publish to unpublish. The second is a viewer's **idle share**, while idle sharing is allowed. `release_player` or the cast's unpublish turns the play's hold into one. It is released when the viewer starts watching something else: `hold_for_player` on another torrent, `moved_elsewhere`, or a cast of theirs published. There is one per viewer, in memory only. It counts only while `idle_sharing_allowed()`, which is asked at each reconcile and never stored. The third is a body being delivered: a stream response registered from `on_stream_start` to `on_stream_end`, or a read not yet ended. That is what starts and keeps a torrent for a stream with no player token. A cache clear sets aside the ones from before it until a stream starts on the torrent again (`BackendEngineFS::cleared`).

  It is never the liveness cell (`retention::live`, which any open moves and which decides windows only), and there is no clock. A torrent that nothing holds, idly shares, delivers or pins stops at the next tick. A gap in the reads never stops a held torrent. The hysteresis stores no bit. Whatever needs a torrent running now awaits `reconcile_hash(.., PlaybackStart)` after registering its activity. Ending what a torrent shares is a reconcile too (`EndShares`: stop, make the advertised set again, restart at once if still wanted, then take the bytes), never a stop made anywhere else. Every path that opens a torrent reader registers a stream first. `routes/stream.rs` and `sources/torrent.rs` are the two. Grep `try_get_file_with_intent` and `try_get_file_unshared` before adding a third. A pre-want's background stream (`Engine::prewant`, `TorrentHandle::prefetch`) is nobody's position. It registers no stream, holds no torrent and keeps none of its pieces. The session's upload switch is `idle_sharing_allowed() || playback_is_live() || a_torrent_download_is_running()` (`apply_upload_switch`, where `idle_sharing_allowed` is `seedingEnabled` and not held). It is recomputed on every tick and never stored.
- **The activity light reads the connection, never the disk** (`TorrentHandle::transfer_totals`, librqbit's peer counters). It does not read storage reads, or `downloaded`, which grows through a hash check. It is judged in Rust over a window, with playback absent over the same window. Playback is checked two ways: live readers and stream responses at each reading, and stream starts between readings (`playback_starts`), so a short play between two polls is still seen. A download of what is not a torrent counts its filler's origin bytes on the way down (`ProxySource::counting_into`). Nothing else fetched over HTTP counts. The upload switch is one for the session. It is on while playing or while a torrent download is on its way. Otherwise it is on only with `seedingEnabled` on and not held (`set_idle_sharing_held`, the app's background hold on a handheld). What runs then is only what is held or pinned, so idle sharing is the pinned downloads' and each viewer's idle share (the last thing they watched). It is a peek: it touches no idle clock and creates nothing. `playback_is_live` is the live fields only, and must never grow to include the last-chosen file.
- **What a panel is told** (`stream_numbers.rs`) dispatches on the URL's shape through the same parsers the routes use, keeps no state, and every absence is `null`, never a zero. Transfer totals are this session's and are not persisted.
- **HTTPS trusts Mozilla's compiled-in roots plus the platform's store, read once in Rust**, through `enginefs::http_client_builder`. Never build a bare `reqwest::Client`. `clippy.toml` refuses every other constructor, and `enginefs/tests/tls_roots.rs` proves the platform verifier is never built. Android's verifier downloads CRLs in Java per handshake, measured as the GC storm behind an ANR.
- **An id is resolved once and asked by peek.** `register` does no I/O; `resolve` does the work and keeps the answer on the entry (`Entry::resolved`, a copy beside the resolve lock). Every question asked by id -- `media_stream_numbers`, the `note_media_*` calls, `note_media_position` -- reads `Registry::peek`, which resolves nothing and waits for nothing, so a panel's poll is never I/O and never lost to a resolve under way. No HTTP route takes a `MediaSpec` or reaches the registry (`media_local.rs`).
- **The resume pre-want asks and keeps nothing.** `set_resume` before `open_reader` makes a played torrent reader ask for the resume point at its open (`media::prewant` plans; `Engine::prewant` walks it through the backend's background stream). It is ordinary cache content: it holds no torrent, registers no stream and protects nothing but the step being asked for. Where a session on a file ended is `note_media_position`'s, in `read-positions.json` beside `settings.json`, the last `MEMORY_CAP` (64) files.
- **The DHT is a peer source, not a requirement, and a dead one stays quiet.** librqbit's per-attempt DHT and UPnP warnings are pinned to `error`, and `diagnostics::dht_health` says the conclusion once. The bootstrap list is the two hosts measured to answer (a host is added only with a `ping` behind it). `backend/dht_bootstrap.rs` resolves the names itself, and hermetic callers use `BootstrapResolvers::offline()`. UPnP is requested only for a `Fixed` listen port.
- **`btMaxConnections` is 160 (40 peers per torrent) and applies live. Lean mode shrinks, it does not stop.** `set_background(true)` caps peers at `LEAN_PEER_LIMIT` and prunes the table. It keeps every torrent live and seeding, and a repeated `Lean` is a no-op. Prune before lowering, never after, or `Full` has nobody to re-dial.
- **The `server` crate is a plain `rlib`**: no `cdylib`, no JNI; xtremio owns the FFI and the Android initialisation.
